# 🎮 GameMatch AI

Умный помощник, который подбирает видеоигры по обычному описанию («хочу атмосферное, как Hollow Knight, но короче»).
Проект по курсу «LLM-агенты · 2026». Реализует всё, что описано в презентации: диалоговый агент → уточнение
контекста → RAG-поиск (FAISS) → ранжирование → топ-5 с объяснением.

## Как это работает

```
свободное описание
      │
      ▼
 ┌──────────┐  не хватает данных   ┌──────────┐
 │ понять   │ ───────────────────► │ уточнить │ → вопрос пользователю (1–3 вопроса)
 │ (LLM +   │                      └──────────┘
 │ правила) │  всё ясно
 └──────────┘ ──────────────┐
                            ▼
         ┌──────────┐   ┌──────────┐   ┌───────────┐
         │ найти    │ → │ ранжиро- │ → │ объяснить │ → топ-5 + «почему подходит»
         │ (FAISS)  │   │ вать     │   │ (LLM+guard)│
         └──────────┘   └──────────┘   └───────────┘
```

* **Граф агента** — LangGraph (`gamematch/agent.py`). Если LangGraph не установлен, тот же граф выполняется встроенным исполнителем.
* **Память диалога** — профиль игрока по `session_id`: платформа, сложность, бюджет, кооператив, длительность, игры-образцы.
* **«Как X, но Y»** — игра X ищется в базе по названию/алиасу, её вектор подмешивается в запрос, а Y («короче», «проще», «дешевле») превращается в ограничения.
* **RAG** — эмбеддинги OpenAI (`text-embedding-3-small`) + индекс FAISS по базе игр. Ранжирование гибридное: близость по смыслу + совпадение с тегами + рейтинг + сложность.
* **Доверие (почему не выдумывает)** — названия, годы, платформы и цифры в ответе берутся из базы, а не из LLM. LLM пишет только короткое пояснение, которое проходит проверку (`explain.py → guard`): нет чужих названий игр и нет чисел, которых нет в карточке игры. Не прошло проверку — подставляется шаблон из фактов базы.
* **Офлайн-режим** — без ключа OpenAI всё работает на правилах и локальном TF-IDF-поиске (для разработки, тестов и демо).

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # впишите OPENAI_API_KEY (можно не вписывать — будет офлайн-режим)

streamlit run streamlit_app.py  # интерфейс: http://localhost:8501
# или REST API:
uvicorn gamematch.api:app --reload   # документация: http://localhost:8000/docs
```

Docker: `docker compose up --build` → интерфейс на `:8501`, API на `:8000`.

Пример диалога через API:

```bash
curl -s localhost:8000/chat -H 'content-type: application/json' \
  -d '{"session_id":"demo","message":"Хочу атмосферное, как Hollow Knight, но короче"}'
# → агент задаёт 1–3 уточняющих вопроса
curl -s localhost:8000/chat -H 'content-type: application/json' \
  -d '{"session_id":"demo","message":"ПК, средняя, до 1000 рублей"}'
# → топ-5 игр с объяснениями
```

Реплики, которые понимает агент: «подешевле», «посложнее», «ещё варианты» (без повторов), «заново» (сброс).

## База игр

В `data/games.csv` лежит **демо-база из 61 игры** (названия, жанры, теги, платформы, ориентировочные длительность и оценка).
Цифры приблизительные и нужны только для демонстрации. Слайды обещают 5 000+ игр — для этого:

```bash
python scripts/import_csv.py --src steam_games.csv --out data/games_5000.csv --limit 5000
# если колонки в вашем файле называются иначе — см. --map в `python scripts/import_csv.py -h`
GAMEMATCH_DATA=data/games_5000.csv python scripts/build_index.py   # посчитать и закэшировать эмбеддинги
```

Формат CSV: `id,title,aliases,year,genres,tags,platforms,difficulty,price_tier,hours,coop,rating,description`
(списки через `;`; `difficulty`: easy/medium/hard; `price_tier`: free/low/mid/high; `coop`: 0/1; `rating`: 0–100).
Теги импортированной базы будут английскими: для русских запросов используйте эмбеддинги OpenAI (они мультиязычные).

## Проверка качества

```bash
python -m unittest discover -s tests -t .      # 22 теста, работают без сети
python -m evaluation.evaluate --json evaluation/report.json
```

`evaluation/testset.json` — 15 диалогов (сценарии из слайдов: новичок, опытный игрок, «как X, но Y»). Скрипт считает
precision@5 (цель ≥ 85 %), faithfulness (цель ≥ 90 %) и p95 времени ответа (цель ≤ 5 с).
До 100 запросов набор нужно дорастить вручную. Это простая проверка; для полноценной оценки подключите RAGAS
(Faithfulness) и соберите CSAT: оценки из интерфейса пишутся в `.cache/feedback.jsonl` (`POST /feedback`).
Стоимость диалога (≤ $0.02) смотрите в кабинете OpenAI: ход с поиском — это 2 вызова `gpt-4o-mini` (понимание запроса
и объяснения) плюс 1 запрос эмбеддинга; ход с уточняющими вопросами — 1 вызов.

## Структура

```
gamematch/
  agent.py        граф LangGraph, диалог, память            ← ядро агента
  profile.py      профиль игрока, правила извлечения предпочтений
  catalog.py      база игр + семантический поиск (инструмент retrieval)
  embeddings.py   OpenAI / локальные эмбеддинги
  vectorstore.py  FAISS (или numpy, если FAISS нет)
  ranking.py      фильтры и ранжирование
  explain.py      объяснения + защита от выдуманных фактов
  llm.py          обёртка ChatOpenAI
  api.py          FastAPI            streamlit_app.py  интерфейс
scripts/          import_csv.py, build_index.py
evaluation/       testset.json, evaluate.py
tests/            unit-тесты (без сети)
```

Соответствие ролям команды из презентации: **RAG & Data** — `catalog.py`, `embeddings.py`, `vectorstore.py`, `scripts/`;
**LLM / Agent** — `agent.py`, `profile.py`, промпты в `agent.py` и `explain.py`; **Backend & Recommendation** —
`api.py`, `ranking.py`, `service.py`; **Frontend & Evaluation** — `streamlit_app.py`, `evaluation/`, `tests/`.

## Ограничения (честно)

* Метрики из `evaluation` посчитаны на демо-базе из 61 игры и маленьком наборе тестов, поэтому это дымовая проверка, а не доказательство «≥ 85 %» на 5 000+ играх. Замерьте всё заново на реальной базе с ключом OpenAI.
* Память диалога хранится в оперативной памяти процесса (после перезапуска сбрасывается; для нескольких воркеров нужен общий стор, например Redis).
* Цены хранятся уровнями (free/low/mid/high), а не точными суммами: актуальные цены в магазинах меняются.
